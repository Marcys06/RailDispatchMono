# [0.0.12a] — Depot buildings, UI/layout and desktop window improvements

Data: 2026-08-31

## Depot

- Depot is now a real world building rather than only a UI spawn button.
- Added `DepotController` for player-built depot instances.
- Added programmatic `DepotRenderer`; no external graphics assets are required.
- Added `TrackBuildMode.Depot`.
- `9` / NumPad `9` activates depot construction mode.
- Left click places a depot building.
- Right click on a depot removes it; Shift + right click is also supported.
- Existing depot model remains suitable as a future route origin for `0.0.13`.

## Passenger floating text

- Passenger exchange is intended to be represented independently per wagon.
- Boarding is displayed as `+X` and alighting as `-X`.
- The zero/net-change case must not replace individual boarding/alighting events.
- Existing floating text continues to use programmatically rendered `SpriteFont` text with upward movement and fade-out.

## UI / Window

- Default desktop window increased from `1280x720` to `1600x900`.
- Desktop window is now user-resizable through the native MonoGame window.
- Settings now expose window-size presets: `1280x720`, `1600x900`, `1920x1080`.
- Window size is persisted with the existing settings system.
- HUD/layout work continues to avoid hard-coded assumptions about the old 1280x720 viewport.

MonoGame exposes `GameWindow.AllowUserResizing` specifically for enabling user resizing, and `ClientSizeChanged` for reacting to size changes. citeturn0search0turn0search1

## Documentation

- Documentation is being aligned with the current `0.0.12`/`0.0.12a` implementation.
- Obsolete statements about stations, passengers, pause, signals, train movement and desktop-only runtime are being removed from the current-state documentation.

## Known limitations

- Route planning is not implemented yet; this remains the main target of `0.0.13`.
- Coupling/decoupling is not implemented yet.
- Passenger demand is still generated by the random provider; city-based demand is intentionally reserved for a future city system.
- The current UI still uses programmatic rectangles/text rather than external UI art assets.
