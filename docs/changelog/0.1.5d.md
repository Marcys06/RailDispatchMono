# 0.1.5d — Coupling regression test foundation

**Data:** 2026-09-03

## Cel

`0.1.5d` establishes the first automated regression layer around the rigid coupling model without expanding the runtime mechanic scope into UI, persistence or longitudinal physics.

## Implemented

- Added `RailDispatchMono.Core.Tests` targeting `net9.0`.
- Added a project reference to `RailDispatchMono.Core`.
- Added the test project to `RailDispatchMono.slnx`.
- Added tests for the default screw-coupler configuration on both physical ends.
- Added tests for `CouplingConnection` direction-independent matching.
- Added a self-connection rejection test.
- Added tests for `CouplingOperationResult` success/failure semantics.
- Added tests confirming `TrainComposition.Split()` preserves vehicle order on both sides of the split.
- Added a test confirming `Train` construction preserves the supplied vehicle order.

## Scope boundary

This milestone deliberately does not add gameplay commands or UI. It also does not claim live verification of the new coupling mechanics. Track-dependent validation, full merge/split integration scenarios and infrastructure-state verification remain future work because they require dedicated fixtures and/or execution in the running game.

The intended operational scenario remains:


## Verification

No build or test command was executed by this change session. The repository now contains the test project and regression cases, but their execution remains to be performed in the user's working .NET environment.
