# 0.1.6e — Coupling/decoupling stabilisation

## Cel

Przywrócenie poprawnego coupling/decoupling po zmianach z linii `0.1.6` oraz usunięcie regresji dotyczących lokomotyw.

## Naprawione

- `TrainComposition.SetLocomotive(...)` po wstawieniu lub podmianie lokomotywy odbudowuje runtime couplingi między sąsiednimi pojazdami.
- Coupling nie opiera już kolejności scalania na obecności lokomotywy. Kolejność `Composition.Vehicles` pozostaje fizycznym porządkiem składu.
- Kandydaci coupling są ograniczeni do granicy `Rear -> Front`, ponieważ tylko taki zapis pozwala scalić dwa składy bez odwracania ich list pojazdów.
- Przy scalaniu stare runtime connection są czyszczone, a następnie odbudowywane na podstawie nowej kolejności pojazdów. Zapobiega to pozostawaniu połączeń na nieprawidłowych końcach po merge.
- Decoupling rozpoznaje punkt podziału na podstawie sąsiednich indeksów pojazdów oraz faktycznego runtime connection, zamiast wymagać konkretnej kombinacji `Rear/Front`. Dzięki temu działa również dla połączenia lokomotywa–wagon.
- Limit coupling pozostaje stały: `6 km/h`.
- Limit decoupling pozostaje bez zmian: poniżej `6 km/h`.

## Kontrakt

- `Composition.Vehicles` nie jest odwracane podczas coupling ani decoupling.
- Lokomotywa i wagon używają standardowego kompatybilnego couplera (`Screw`), więc połączenie lokomotywa–wagon jest obsługiwane tak samo jak wagon–wagon.
- Runtime coupling nadal nie jest zapisywany w save/load.
- Nie dodano fizyki luzu, sił zderzenia ani animacji sprzęgania.
