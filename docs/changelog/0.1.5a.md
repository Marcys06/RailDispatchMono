# 0.1.5a — Rigid coupling and decoupling foundation

**Date:** 2026-09-03

## Implemented

- Intrinsic `VehicleEnd` (`Front`, `Rear`).
- Static per-end coupler capability via `CouplingSpecification`.
- Runtime `VehicleCouplingState` owned by each vehicle.
- `CouplingConnection` between two concrete vehicle ends.
- Typed validation and operation results.
- Endpoint geometry derived from the existing `Train.GetVehicleTransform()` model and vehicle `Parameters.Length`.
- Distance and facing/alignment checks.
- Static compatibility rules: matching non-`None` coupler types only.
- Coupling only at outer train boundaries.
- Merge of two trains into one while preserving consist order.
- Decoupling at an actual runtime coupling connection, producing a new train for the detached section.
- `[COUPLING]` diagnostics.
- Existing RadioStop remains the independent safety mechanism for maneuvering trains.

## Deliberate limitations

This stage is a rigid mechanical foundation. It does not implement slack, impact, force transmission, coupling delay, brake-pipe propagation, persistence or UI commands.

Automated tests and gameplay/infrastructure verification remain outstanding and are tracked in `docs/coupling-decoupling-work.md`.

## Verification boundary

The repository was edited directly on `master`. No local `dotnet build` was run in this environment.
