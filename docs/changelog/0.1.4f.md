# 0.1.4f — Depot Myra migration

**Data:** 2026-09-01

## Problem fixed

`0.1.4e` added `DepotScreen` and `MyraDepotView`, but the actual click path in `InputManager` still opened the pre-Myra `DepotTrainMenu`. That left the old three-preset train flow active and made the new Myra builder unreachable during normal Depot interaction.

## Depot flow

The existing Depot click path now raises `InputManager.DepotSelected`, which opens `DepotScreen` directly.

The legacy `DepotTrainMenu` SpriteBatch implementation has been removed. Its three hardcoded presets — short, standard and long — no longer exist.

The complete Depot train-creation flow is now:

1. click an existing Depot;
2. open full-screen `DepotScreen`;
3. choose any locomotive from `RollingStockCatalog`;
4. add/remove any number of passenger wagons;
5. inspect live physical statistics;
6. create the composition through `TrainManager.CreateTrainFromComposition()`;
7. spawn it on the adjacent free track cell;
8. close the screen and restore the gameplay Myra root.

No preset-based or hardcoded train creation remains in `InputManager`.

## UI ownership

`DepotScreen` remains a normal `GameScreen`, not a popup. It uses the existing shared `MyraUIManager` and `Desktop`; no second Myra host was introduced.

While the Depot screen is active, `GameplayScreen` is covered by the screen manager, so gameplay simulation does not advance. Closing the Depot restores the previous gameplay Myra root.

## Train creation authority

The old `InputManager.SpawnTrain()` path, including its hardcoded EU06-style `VehicleParameters`, was removed. Depot-created trains now have a single creation authority: `TrainManager.CreateTrainFromComposition()`.

This keeps rolling-stock selection, physical parameters and consist composition in the `Game/RollingStock` + `TrainComposition` domain introduced in `0.1.4e`.

## Save metadata

`MapSaveService` now writes `GameVersion = "0.1.4f"`.
