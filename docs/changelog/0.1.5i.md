# 0.1.5i — Fixed shunting control and cursor-targeted decoupling

**Date:** 2026-09-03

## Changes

- Removed the configurable `3 / 4 / 5 km/h` coupling speed selection from `F6 / F7 / F8`.
- Coupling now uses a fixed `6 km/h` shunting limit with no runtime speed-selection command.
- `X` decoupling is now restricted to trains moving below `6 km/h`.
- The `< 6 km/h` decoupling limit is enforced in `CouplingService`, so the rule also applies to direct domain calls and not only keyboard input.
- `F6` is now manual shunting control: while held with the cursor over a train, that train accelerates toward `3 km/h` and bypasses the automatic RadioStop/collision stop path.
- `F6` manual shunting is cursor-targeted; other trains continue through normal safety processing.
- `X` now targets the wagon currently under the cursor instead of the last `C` coupling or the oldest available runtime connection.
- For a wagon with two runtime couplings, the rear coupling is preferred so `X` splits the consist after the hovered wagon; the front coupling is used when no rear connection exists.
- `X` rejects the command when no wagon is actually under the cursor.

## Existing behavior retained

- `C` still selects the nearest valid outer-train coupling candidate.
- Runtime coupling compatibility remains based on physical `CouplerType` compatibility.
- Automatic adjacent runtime couplings in pre-built consists remain unchanged.
- Detached consist vehicle positions remain preserved after decoupling.

## Verification boundary

The code changes were inspected against the current train movement, RadioStop, collision, coupling and rendering/input paths. A live build was not run in the current environment because NuGet/package restore requires unavailable network access.
