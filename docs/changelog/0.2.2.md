# 0.2.2 — timetable execution, dispatcher diagnostics and locomotive timetable editor

## Locomotive timetable editor

- Added a dedicated Myra locomotive timetable editor.
- F9 opens the editor for the selected locomotive train.
- Points can be added, removed and reordered.
- Stations can be changed per point.
- Arrival and departure can be adjusted independently.
- Timetable can be enabled/disabled before saving.
- Validation requires at least two ordered points and a positive cyclic duration.
- Editing is transactional: the draft is committed only after validation succeeds.

## Dispatcher and blocks

- `RailwayDispatcher` now keeps an explicit FCFS request queue.
- A train waits when the next block is occupied, reserved or cooling down.
- A queued train cannot be overtaken by a later request for the same dispatcher cycle.
- Queue state is exposed for diagnostics.
- Existing `BlockController` and `Block` ownership remain authoritative.

## Timetable runtime

- Runtime now records actual departure time and observed travel duration.
- Expected arrival/departure for future points include propagated positive delay.
- Early arrival remains non-negative for propagated delay and therefore does not make later planned points artificially early.
- Station departure control uses the expected departure derived from runtime state.

## Diagnostics

- F10 opens a full railway diagnostics view.
- Every block is shown as `FREE`, `RESERVED` or `OCCUPIED`, with cooldown and owner details where applicable.
- Dispatcher FCFS queue is shown.
- Every signal aspect is shown together with its associated block state.
- Train timetable runtime and dispatcher state are shown together.

## Player responsibility

- The dispatcher still does not operate switches or change signal aspects.
- Coupling/decoupling, RadioStop semantics, manual driving and infrastructure decisions remain player-controlled.
- Automatic timetable operation only controls schedule timing and station braking/dwell already owned by the existing railway systems.

## Compatibility

- Backward compatibility with old saves is not required.
- The HUD and diagnostics are presentation changes and do not require a separate compatibility layer.

## Verification

A Windows build and live gameplay verification remain required. In particular, verify F9 timetable editing, cyclic execution, early/late arrivals, block contention with two trains, F10 diagnostics and resized Myra layouts.
