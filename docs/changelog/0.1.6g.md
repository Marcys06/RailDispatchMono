# 0.1.6g — Runtime safety and geometry cleanup

## Cel

Ujednolicenie krytycznych ścieżek runtime po stabilizacji coupling/F7 oraz usunięcie artefaktów, które utrudniały jednoznaczne określenie aktualnej architektury.

## Zmiany

- usunięto `RailDispatchMono.sln.bak`;
- usunięto oba śledzone `debug_log.txt` oraz `full_log.txt`;
- usunięto pusty `Effects/Particle.cs`;
- usunięto pusty `TrainDirectionPreservation.cs`, ponieważ implementacja zachowania pozycji kierunku znajduje się w `TrainDirection.cs`;
- dodano ignorowanie lokalnych `*_log.txt` i `*.sln.bak`;
- `RadioStop` jest twardym zabezpieczeniem w normalnym `Train.Update(...)`; aktywny stop nie może zostać nadpisany przez automatyczne rozpędzanie;
- F6 pozostaje świadomym wyjątkiem: manual shunting może wyczyścić `RadioStop` dla wybranego pociągu;
- `TrackConnections.GetOppositeDirection()` jest jedną metodą rozszerzającą w `Game/Railway`;
- `TrainComposition.EffectiveMaxSpeed` jest źródłem bazowego Vmax składu, a limit sygnału jest osobnym stanem runtime;
- usunięto duplikat `_lastSignalSpeed`;
- konwersja długości legacy grid → metre korzysta z `SimulationScale`;
- geometria coupling centralizuje uwzględnienie `VehicleOrientation`;
- coupling/decoupling i F7 zachowują pozycje pojazdów zamiast rekonstruować je z kolejności listy;
- Android, WindowsDX i iOS pozostają w repozytorium jako hosty platformowe. Nie usunięto ich tylko dlatego, że obecne `.sln`/`.slnx` zawierają Core + DesktopGL.

## Kontrakt

- `Composition.Vehicles` pozostaje jedynym autorytatywnym kontenerem kolejności fizycznej.
- `CompositionOrder` jest metadanymi tej kolejności, a nie drugim źródłem stanu.
- `TrainComposition.EffectiveMaxSpeed` opisuje zdolność składu; sygnał ogranicza aktualny target.
- `SimulationScale` jest granicą między metrami fizycznymi i komórkami mapy.
- `RadioStop` blokuje normalny ruch automatyczny.
- F6 jest jedynym świadomym trybem manualnym omijającym automatyczny RadioStop/collision stop dla wybranego pociągu.
- Historyczne milestone'y nie są przepisywane.

## Weryfikacja

Nie ma dedykowanego projektu automatycznych testów Core ani aktywnych check runów CI potwierdzających ten stan. Po zmianach runtime wymagane są build rozwiązania oraz test live gameplay.
