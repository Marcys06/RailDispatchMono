# 0.1.0 — Stabilization release

**Date:** 2026-08-31

## Scope

`0.1.0` closes the planned `0.0.16` feature series. The feature work required for the first playable baseline is considered complete. This release is intentionally a stabilization milestone: subsequent changes under `0.1.x` should primarily address bugs, regressions, polish and maintenance.

## Included functionality

### Persistence and save slots

- Save data is stored as separate JSON files inside an individual save directory.
- `metadata.json` identifies the save and stores save metadata.
- Save data is versioned through `schemaVersion`.
- Runtime persistence covers the implemented map/infrastructure, trains and consists, vehicle positions, wagon routes/schedules, passenger state and simulation time (`GameDay` / `GameTime`) where supported by the current implementation.
- Save/load is integrated with the game flow and pause menu.
- Invalid or incomplete save data is rejected with a user-facing notification instead of silently loading partial state.
- Auto-save is intentionally disabled.

### Main Menu and startup flow

- Application startup enters the Main Menu.
- Main Menu provides New Game, Load Game, Settings, About and Quit.
- New Game immediately creates a fresh empty game state; no confirmation dialog is required.
- Load Game works with the available save directories.
- Screen transitions remain owned by `ScreenManager`.

### Depot and train creation

- Depots are world objects and act as the entry point for train creation.
- The existing depot workflow supports creation of multiple trains from a depot.
- Train consists and their runtime state participate in the persistence system.

### Passenger exchange feedback

- Passenger exchange is handled at wagon level.
- When a wagon's passenger count changes, floating notifications can be displayed at the affected wagon.
- Boarding is represented as `+X` passengers and leaving as `-X` passengers.

### Pause and screen management

- `ESC` toggles pause.
- Pause is implemented as a managed overlay rather than a second game loop.
- Pause stops simulation progression.
- Save/Load actions remain integrated with the pause flow.

## Stability status

The current game is considered functional within the intended prototype scope. Minor defects may remain and are tracked as normal bug-fix work; they do not redefine the `0.1.0` feature baseline.

## Constraints for 0.1.x

- Do not expand the feature scope under `0.1.0` merely because an implementation detail is imperfect.
- Preserve existing APIs unless a concrete bug requires an API correction.
- Verify actual source behavior before modifying architecture.
- Keep historical changelog entries intact.
- Update current-state documentation when behavior changes.
