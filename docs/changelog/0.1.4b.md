# 0.1.4b — Simulation scale and simulation clock

## Scope

`0.1.4b` continues the train-mechanics work from `0.1.4a` and introduces a single physical scale for the map plus authoritative simulation-time deltas for gameplay.

## Spatial scale

- Added `SimulationScale` as the central conversion boundary between map cells and physical metres.
- Current scale: **1 map cell = 10 metres**.
- Map geometry itself is unchanged; only its physical interpretation changes.
- Train movement converts physical speed (`m/s`) into grid-cell movement through `MetersPerGridCell`.
- Train composition positioning converts vehicle lengths from metres to grid cells.
- Train rendering scales vehicle length to the new physical cell scale.
- Signal distance used by braking calculations is converted from route cells to metres before applying the existing physical braking formula.
- Block `LengthInMeters` now derives from the same central spatial scale instead of using an independent `100 m/cell` constant.

## Simulation time

- `GameClock` remains the authoritative simulation clock.
- The existing documented baseline is retained: **5 simulation seconds per real second at x1**.
- x2 and x5 multiply the baseline through `SimulationSpeed`.
- `GameClock.Update()` now returns the actual elapsed simulation seconds, and `GameplayScreen` passes that delta to gameplay systems.
- Train movement, acceleration and braking therefore run on simulation time instead of raw wall-clock `GameTime.ElapsedGameTime`.
- The Myra clock continues to display the same authoritative `GameClock` state.

## Preserved mechanics

- Train physical speed values remain in metres per second and are displayed as km/h.
- Existing signal aspects and braking formulas remain in physical units.
- Existing curve geometry remains expressed in grid coordinates; its physical length follows the new cell scale.
- Existing StationController and BlockController ownership is not replaced by the time/space migration.

## Audit notes

The initial scale audit found two important existing assumptions:

- train movement previously treated one grid unit as one metre;
- `Block.LengthInMeters` independently treated one grid unit as 100 metres.

`0.1.4b` removes those conflicting interpretations from the migrated paths by centralizing the conversion.

## Verification target

The build should be checked before treating `0.1.4b` as stable. Functional checks should include:

1. 100 km/h still represents 27.78 m/s.
2. A train travels 10 metres per grid cell.
3. Vehicle spacing and rendering remain proportional after the scale change.
4. Signal braking still uses metres, not raw grid cells.
5. x1/x2/x5 advance both the clock and train simulation consistently.
6. Pause stops simulation progression.
7. Stop, Clear, StationController and BlockController behavior from `0.1.4a` remains intact.
