# 0.1.6d — Passenger journey continuity

## Cel

Przygotowanie modelu pasażera do przyszłych przesiadek bez uzależniania pasażera od identyfikatora pociągu. Wagon pozostaje stabilną jednostką przewozową, a pociąg jest wyłącznie bieżącym kontekstem operacyjnym.

## Zmiany

- Naprawiono `DefaultPassengerService`: `Wagon` jest poprawnie rozpoznawany przez namespace `RailDispatchMono.Core.Game.Train`.
- Boarding nadal odbywa się wyłącznie przez konkretny wagon i jego własną trasę.
- Dodano `Wagon.CanContinueJourneyTo(...)` jako jawny punkt kontroli ciągłości podróży pasażera względem aktualnej pozycji trasy wagonu.
- Dodano `PassengerManager.GetTransferCandidates(Train)` jako diagnostyczny punkt wejścia dla przyszłego systemu przesiadek.
- Diagnostyka transferowa nie wybiera pociągu i nie przenosi pasażera. Nie zmienia zasady, że pasażer jest przypisany do wagonu.
- Coupling i decoupling nadal nie powodują migracji pasażerów.
- Przywracanie pasażerów z zapisu omija normalną walidację boardingu, ponieważ zapis reprezentuje już istniejący stan podróży.
- `RuntimeSaveData.GameVersion` został podniesiony do `0.1.6d`.

## Naprawione błędy

- CS0246: `Wagon` w `DefaultPassengerService.cs`.
- CS1501 po zmianie API `Wagon.TryBoard(...)` w `RuntimeSaveService.cs` — odtwarzanie korzysta teraz z dedykowanego `RestorePassenger(...)`.

## Zakres poza 0.1.6d

- Nie dodano automatycznych przesiadek.
- Nie dodano wyboru pociągu przez pasażera.
- Nie dodano ekonomii, taryf ani przychodów.
- Nie zmieniono formatu tras wagonów.
- Nie zmieniono mechaniki coupling/decoupling.
