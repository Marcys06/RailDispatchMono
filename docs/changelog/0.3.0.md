# 0.3.0 — Infrastructure maintenance

**Data:** 2026-09-14

## Added

- Added `InfrastructureMaintenanceManager` as the runtime owner of track wear simulation.
- Added simulation-time wear accumulation for `TrackCell` infrastructure.
- Added traffic-sensitive wear: occupied tracks wear faster than unused tracks.
- Added wear modifiers for `LineClass`, `TrackType` and `TractionSystem`.
- Added `Good`, `Warning` and `Critical` infrastructure states.
- Added F10 maintenance summary and worst-track diagnostics.
- Added `NAPRAW KRYTYCZNE` and `NAPRAW WSZYSTKIE` actions to F10.

## Persistence

- Continued using `map.json` schema 3.
- Existing `TrackCell.WearPercent` persistence is reused; no save migration was introduced.

## Domain boundary

- `GameMap.Maintenance` owns maintenance simulation.
- `TrackCell` remains the owner of its current wear value.
- Dispatcher, blocks, signals, switches, routes and timetable logic remain independent.
- Maintenance does not automatically close tracks or modify dispatch decisions.
