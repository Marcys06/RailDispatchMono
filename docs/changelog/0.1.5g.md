# 0.1.5g — Automatic runtime couplings for complete consists

**Date:** 2026-09-03

## Purpose

A `Train` may be created directly from a complete `TrainComposition`. Previously, such a composition could contain multiple vehicles while having no runtime `CouplingConnection` objects between adjacent vehicles. That made `X` unable to split a formation that had never been assembled with `C`.

## Implemented behavior

`TrainComposition.AddVehicle()` now attempts to establish the physical runtime connection between the previously last vehicle and the newly added vehicle.

The connection is created only when:

- the previous vehicle's `Rear` end is free;
- the new vehicle's `Front` end is free;
- both ends expose a supported coupler;
- both ends use the same `CouplerType`.

This is independent of wagon display names or wagon classes. Therefore a formation such as:

`EP07 <-> 1KL <-> 2KL <-> 3KL`

is represented as one ordered `TrainComposition` with three wagon-to-wagon/locomotive-to-wagon runtime connections, assuming the physical coupling specifications are compatible.

## Decoupling

`X` can now resolve any initialized adjacent runtime connection and split the train at that boundary. The operation remains delegated to `CouplingService.Decouple()`.

The split boundary connection is cleared. Connections inside the retained and detached sections remain valid. When the detached composition is constructed, already occupied runtime connections are not replaced with duplicates.

## Explicit coupling

`C` remains responsible for coupling two separate trains. Because the boundary connection is established before the trailing vehicles are appended, the composition builder detects the occupied ends and does not create a duplicate connection.

## Scope

This milestone does not change:

- `C` candidate selection;
- shunting speed limits;
- coupler compatibility rules;
- geometry/alignment validation for coupling two separate trains;
- dynamic coupling forces, slack, animation or brake-pipe simulation;
- coupling persistence.

## Verification

The change was inspected against the existing `TrainComposition`, `VehicleCouplingState`, `CouplingConnection` and `CouplingService` architecture. A live .NET/MonoGame build was not executed in this environment because package restore requires external network access.
