# 0.1.5x — Train travel direction state and non-destructive F7 reversal

**Data:** 2026-09-03

## Problem

The previous F7 implementation mixed travel direction with formation-position reconstruction. After reversing, a consist could visually change from `[A][B][B][B]` to `[B][B][B][A]`, even though `Composition.Vehicles` itself was not intentionally reordered.

## Changes

- Rebuilt F7 as a train travel-direction state change rather than a composition mutation.
- `Train.Direction` is now the authoritative current travel direction.
- Added `Train.IsReversed` as explicit runtime state for the forward/reverse travel mode.
- F7 never reorders `Composition.Vehicles`.
- F7 never moves the physical vehicle positions at the instant of reversal.
- The existing first vehicle remains the train's simulation reference point; reversing changes only the direction in which that reference point moves.
- Vehicle transforms are preserved by vehicle index for the stopped reversal frame, then normal trajectory-based formation reconstruction resumes as soon as the train moves.
- `GetVehiclePositions()` now uses the same authoritative `GetVehicleTransform()` result as rendering, removing the previous mismatch between fixed one-cell spacing and vehicle-transform spacing.
- Locomotive `VehicleOrientation` is no longer toggled by F7. Travel direction and vehicle orientation are no longer conflated by the F7 command.
- Runtime saves persist `IsReversed` so a reversed train retains its travel state after loading.
- Existing composition order and coupling state remain independent from travel direction.

## Expected behavior

Before F7:

```text
[A][B][B][B]  →
```

After F7:

```text
[A][B][B][B]  ←
```

The world coordinates and logical vehicle order remain unchanged at the reversal moment.
