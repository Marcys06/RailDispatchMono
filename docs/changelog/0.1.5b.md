# 0.1.5b — Coupling stop behavior

**Data:** 2026-09-03

## Coupling / decoupling

- Coupling now explicitly stops both participating trains through the existing `RadioStop` mechanism before changing composition.
- The merged train starts from `0 m/s` instead of inheriting shunting momentum.
- Decoupling stops the original train before splitting the composition.
- The newly created detached train is registered at `0 m/s` and receives `RadioStop`.
- Vehicle order and concrete vehicle-end coupling state remain unchanged by this stage.

## Scope

This stage remains limited to rigid coupling/decoupling mechanics. Coupling delay, slack, impact forces, longitudinal dynamics, brake-pipe propagation, UI and persistence remain outside `0.1.5b`.

## Verification boundary

Repository code was updated directly on `master`. The project's `dotnet build` is reported by the developer as working locally; no local build was executed by this session.
