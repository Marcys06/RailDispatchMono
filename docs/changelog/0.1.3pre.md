# 0.1.3pre — Myra Gameplay UI stabilization

**Date:** 2026-09-01

This is the current pre-release milestone after the `0.1.3a`–`0.1.3e` development stages and the latest developer bugfix.

## Completed

- Gameplay HUD migrated to Myra.
- Simulation clock migrated to Myra; legacy clock presentation removed.
- `GameDay` displayed by Myra.
- Simulation speed controls `x1`, `x2`, `x5` are Myra buttons.
- Build tools are presented through a collapsible Myra panel.
- Train and station lists are presented through Myra only; duplicate legacy train/station HUD presentation was removed.
- Station entries display waiting passenger counts.
- Selecting a train or station focuses the camera on the selected object's world-space center.
- Main Menu → Gameplay Myra lifecycle is stable; the Main Menu root does not remain over gameplay.
- Pause is owned by `GameplayScreen` and presented through `MyraPauseView`.
- Resume, Save, Load and Quit use the gameplay-owned pause action path.
- Save/Load remain behind the existing `MapSaveService` persistence boundary.

## Documentation audit — 0.1.3pre

The maintained documentation files `01`–`18` were audited against the current repository state. The audit found several documents still describing the earlier `0.1.2a`/`0.1.2j` Myra state. Those stale claims were corrected where they contradicted the current implementation.

### Corrected areas

- Architecture/lifecycle documentation now describes the shared Myra `Desktop`, active root model and current gameplay/pause ownership.
- Screen documentation now treats pause as `GameplayScreen` state rather than a popup `PauseScreen`.
- Input documentation now reflects Myra pointer input and the current gameplay controls.
- AI rules/context now use `0.1.3pre` as the current baseline and no longer freeze Myra rules at `0.1.2j`.
- Known-issues documentation no longer presents `0.1.2a` as the current baseline.
- Documentation maintenance now defines current-state snapshots as `pre`-only documents.
- Screens/UI documentation now reflects the migrated gameplay HUD and the removal of duplicate train/station UI.
- The documentation index now lists only `0.1.2pre` and `0.1.3pre` current-state snapshots.

### Files reviewed

`01-project-overview.md`, `02-repository-structure.md`, `03-architecture.md`, `04-runtime-lifecycle.md`, `05-screen-system.md`, `06-input.md`, `07-game-domain.md`, `08-settings-localization.md`, `09-content-platforms.md`, `10-development-workflows.md`, `11-ai-agent-rules.md`, `12-known-issues-and-cautions.md`, `13-code-index.md`, `14-documentation-maintenance.md`, `15-ai-context.md`, `16-screens-and-ui.md`, `17-game-map-and-geometry.md`, `18-platform-hosts.md`.

### Audit result

No documentation item was intentionally marked as implemented merely because a supporting class exists. Where behavior could not be established from the available source inspection, the documentation retains a verification/caution statement rather than inventing a contract.

## Remaining UI migration / known scope

- World-specific radial menus for junctions/signals where still present.
- Legacy world tooltips/floating gameplay text where still used.
- Dedicated train detail window.
- Dedicated station detail window.
- Dedicated wagon-route detail/editor window beyond the existing workflow.
- Depot-specific interaction UI where applicable.
- More advanced train/station visual state and configurable colors.

These remain future work and are not represented as completed by the current HUD migration.

## Version policy

`0.1.3pre` is the consolidated pre-release milestone. Lettered `0.1.3a`–`0.1.3e` stages remain historical. Further changes should normally be bugfixes, polish or mechanic work against this baseline unless a larger feature warrants a new release milestone.
