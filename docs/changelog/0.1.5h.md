# 0.1.5h — Preserve detached consist positions after decoupling

**Date:** 2026-09-03

## Purpose

After `X` decoupling, the detached train was created correctly as a separate ordered composition, but its vehicle transforms could collapse onto the same position. This was caused by the newly created train starting with only its head position in trajectory history.

## Implemented behavior

The detached train now preserves the spatial position implied by the consist at the moment of decoupling. Vehicle transforms are resolved from the train head position, direction and vehicle distance behind the head instead of treating all detached vehicles as if they occupied the same spawn point.

The fix applies to the train's initial/no-travel trajectory state and keeps the existing trajectory-based positioning model for trains that have already moved.

## Decoupling semantics

The following behavior remains unchanged:

- `X` resolves a concrete runtime `CouplingConnection`;
- the composition is split at that connection;
- the split boundary connection is cleared;
- internal runtime connections in each resulting section remain intact;
- the detached section is registered as a separate stopped train.

The change only corrects spatial initialization/presentation of the detached vehicles. It does not introduce teleportation or repositioning of the vehicles to an arbitrary track cell.

## Verification

The repository state was inspected against `Train`, `TrainMovement`, `TrainGeometry` and the coupling command path. A live .NET/MonoGame build was not executed in this environment because package restore requires external network access.
