# 0.1.6pre — Consolidated 0.1.6 pre-release

**Data:** 2026-09-04

## Cel

Zamknięcie linii rozwojowej `0.1.6` jako `0.1.6pre` po stabilizacji modelu pasażerskiego, sztywnego składu, ruchu po trajektorii, F7, coupling/decoupling oraz runtime safety.

## Passenger / Wagon

- pasażer podczas jazdy należy do konkretnego `Wagon`, a nie do `Train`;
- `CurrentWagonId` utrzymuje to powiązanie w stanie runtime/save;
- boarding sprawdza pojemność i zgodność `TrainRoute` z kierunkiem podróży;
- `Wagon.CanContinueJourneyTo(...)` jest jawnym kontraktem ciągłości podróży;
- `PassengerManager.GetOnBoard(Train)` jest widokiem operacyjnym, nie granicą własności;
- `GetTransferCandidates(Train)` jest przygotowanym punktem diagnostyczno-przyszłościowym i nie wykonuje automatycznych transferów;
- load przywraca pasażera bezpośrednio do zapisanego wagonu;
- coupling/decoupling nie przenosi pasażerów między wagonami.

## Consist ordering

- `TrainComposition` jest jedynym autorytatywnym kontenerem fizycznej kolejności pojazdów;
- `Vehicle.CompositionOrder` jest metadanymi tej kolejności;
- F7 nie odwraca listy pojazdów;
- coupling i decoupling zachowują fizyczną kolejność składu;
- `SetLocomotive(...)` odbudowuje sąsiednie runtime connections.

## F7 / movement / geometry

- F7 jest zmianą kierunku ruchu wykonywaną wyłącznie przy `0 km/h`;
- stan `IsReversed` opisuje kierunek podróży i nie rekonstruuje kolejności listy;
- travel head wynika z kierunku/reversal state, a nie ze stałego założenia, że jest nim `vehicle[0]`;
- ruch pojazdu jest liczony względem aktywnego travel head;
- po zmianie kierunku zachowane są dokładne pozycje pojazdów;
- trajektoria jest zasiewana z dokładnych pozycji i uporządkowana według kierunku podróży;
- każdy pojazd pobiera pozycję z własnego dystansu za głową składu;
- rotacja pojazdu wynika z lokalnej stycznej trajektorii;
- głowa składu na łuku korzysta z dokładnej stycznej aktywnego łuku;
- `SimulationScale` jest jedyną granicą konwersji metrów fizycznych i komórek mapy;
- długości pojazdów oraz dystans ruchu korzystają z tej samej konwencji jednostek.

## Coupling / decoupling

- `CouplingService` jest jedyną granicą mutacji operacji sprzęgania i rozprzęgania;
- coupling dotyczy kompatybilnych zewnętrznych granic składu;
- kandydaci są ograniczeni do order-preserving `Rear → Front`;
- limit coupling wynosi `6 km/h`, a decoupling jest dozwolony poniżej `6 km/h`;
- przed merge czyszczone są stare runtime connections;
- po merge odtwarzany jest pełny łańcuch połączeń na podstawie `Composition.Vehicles`;
- decoupling korzysta z sąsiednich indeksów i rzeczywistego runtime connection;
- `VehicleOrientation`, w tym `Reverse`, jest uwzględniane przez geometrię coupling;
- coupling i decoupling zachowują dokładne pozycje świata pojazdów;
- zweryfikowano przypadek wagon + lokomotywa: po merge pozycje i dystanse pozostają spójne również po odbudowie runtime connections.

## Safety / speed

- `RadioStop` jest twardą blokadą normalnego automatycznego ruchu w `Train.Update(...)`;
- F6 jest jawnym trybem manualnego shuntingu i może ominąć automatyczny RadioStop/collision stop dla wybranego pociągu;
- `TrainComposition.EffectiveMaxSpeed` jest autorytatywnym Vmax składu;
- limit sygnału pozostaje osobnym ograniczeniem runtime;
- usunięto duplikat `_lastSignalSpeed`;
- `TrackConnections.GetOppositeDirection()` jest jedną wspólną metodą rozszerzającą.

## Diagnostics

Diagnostyka coupling została rozszerzona o ograniczone snapshoty wysokiej wartości:

- stan obu pociągów przed operacją;
- fizyczną kolejność pojazdów;
- `CompositionOrder`, `VehicleOrientation`, długość i pozycję;
- dystans pojazdu względem travel head;
- transform/rotację;
- stan po merge i po odbudowie runtime connections;
- snapshot trajektorii;
- dedykowany `TrainDiagnostic` omijający zwykły globalny limiter logów dla krótkich, jawnie ograniczonych zdarzeń diagnostycznych.

Diagnostyka nie jest przeznaczona do logowania per-frame.

## Cleanup

- usunięto nieaktualne `.bak`, `debug_log.txt`, `full_log.txt`, pusty `Effects/Particle.cs` i obsolete `TrainDirectionPreservation.cs`;
- dodano ignorowanie lokalnych `*_log.txt` oraz `*.sln.bak`;
- hosty Android, WindowsDX i iOS pozostają w repozytorium.

## Zakres poza milestone

Nie wprowadzono:

- slack action;
- sił uderzenia i pełnej dynamiki wzdłużnej;
- opóźnienia/animacji sprzęgania;
- propagacji przewodu hamulcowego;
- automatycznych transferów pasażerów;
- automatycznego wyboru pociągu przez pasażera;
- ekonomii, taryf i przychodów.

## Weryfikacja

Stan został zweryfikowany przez analizę runtime oraz test live gameplay F7 i coupling. Ostatni test coupling potwierdził spójność pozycji i dystansów bezpośrednio po merge. Brak dedykowanego projektu automatycznych testów Core oraz aktywnych CI check runs oznacza, że pełna walidacja builda wymaga lokalnego builda rozwiązania.

## Status

`0.1.6pre` jest skonsolidowanym snapshotem linii `0.1.6`. Historyczne `0.1.6c`–`0.1.6g` pozostają niezmienione.
