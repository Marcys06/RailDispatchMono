# 0.1.5f — Remove dedicated Core test project

**Data:** 2026-09-03

## Cel

`0.1.5f` removes the dedicated `RailDispatchMono.Core.Tests` project from the runnable solution and aligns the maintained documentation with the current runtime architecture.

## Project structure

- Removed `RailDispatchMono/RailDispatchMono.Core.Tests/RailDispatchMono.Core.Tests.csproj`.
- Removed the dedicated coupling/composition test source files from the repository.
- Removed the test project entry from `RailDispatchMono.slnx`.
- The runtime solution now contains the shared Core project and DesktopGL host used for the current application workflow.

The historical `0.1.5d` changelog remains unchanged because historical lettered stages are immutable. The tests described there were part of that historical stage and are not part of the current repository.

## Runtime coupling/decoupling

No coupling or decoupling runtime behavior was removed. The existing `TrainManager` and `CouplingService` implementation remains the authoritative gameplay path.

Current player commands remain:

- `C` — nearest valid coupling candidate;
- `X` — last coupling created by `C`, with fallback to the first remaining runtime connection;
- `F6` / `F7` / `F8` — `3` / `4` / `5 km/h` shunting limits.

## Documentation

- Added the consolidated `0.1.5pre` current-state snapshot.
- Updated the documentation index and maintenance rules.
- Updated input, domain, AI-agent, known-issues, code-index and AI-context documentation.
- Documented that the current repository has no dedicated automated Core test project.

## Verification

The source changes are structurally limited to project removal and documentation. Live gameplay/build verification remains dependent on the user's local .NET/MonoGame environment.
